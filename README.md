# Help Me Journal Frontend

A React + TypeScript frontend for organizing personal projects and project-based journal containers. The app uses Clerk for authentication, React Query for async state management, and a backend API for project and container data.

## Overview

This frontend provides a minimal but useful planning and reflection workflow:

- sign in with Clerk
- browse a project dashboard
- create, edit, and delete projects
- open an individual project page
- create, view, and manage project containers
- tag containers with mood metadata
- navigate between projects through a sidebar tree

The UI is built with Vite, React, Tailwind CSS, and reusable components styled in the shadcn pattern used by this codebase.

## Features

- Clerk-based authentication gate
- Project dashboard and project cards
- Per-project detail view at `/projects/:projectId`
- Container creation with supported container types and moods
- Query-driven data refresh with TanStack React Query
- Axios client that attaches Clerk JWTs to API requests
- Responsive layout with a dashboard-like interface

## Prerequisites

Before running the app, make sure you have:

- Node.js 18 or newer
- npm
- a running backend API that exposes the project/container endpoints
- a Clerk application with a publishable key

## Environment Variables

Create a `.env` file in the project root with the following values:

```env
VITE_API_URL=http://localhost:3000
VITE_CLERK_PUBLISHABLE_KEY=your_clerk_publishable_key
```

Notes:

- `VITE_API_URL` is the base URL for the backend API.
- `VITE_CLERK_PUBLISHABLE_KEY` is required for the Clerk auth provider.
- The app expects authenticated requests to be sent with a bearer token generated by Clerk.

## Application Flow

The app is organized around a simple flow:

1. A user signs in with Clerk.
2. The app loads the project list from the backend.
3. The user can create projects and open a project detail page.
4. Inside a project, the user can create containers such as journal or technical notes.
5. Containers may include mood metadata and are displayed in project-specific views.

## Project Structure

```text
src/
  App.tsx
  main.tsx
  components/
  hooks/
  lib/
  pages/
  types/
```

Key areas:

- `src/App.tsx` — root app, auth gate, route setup
- `src/pages/HomePage.tsx` — dashboard for creating and viewing projects
- `src/pages/ProjectPage.tsx` — project detail page for containers
- `src/hooks/` — data fetching and mutation hooks for projects and containers
- `src/lib/api.ts` — Axios client setup
- `src/lib/useApiAuth.ts` — Clerk token injection for API requests
- `src/components/` — dashboard cards, dialogs, sidebar, and project tree UI
- `src/types/` — TypeScript DTOs and prop interfaces

## API Expectations

This frontend expects a backend service to provide endpoints compatible with the current client contracts, including:

- `GET /projects`
- `POST /projects`
- `PATCH /projects/:id`
- `DELETE /projects/:id`
- `GET /projects/:projectId/containers`
- `POST /projects/:projectId/containers`
- `PATCH /containers/:containerId`
- `DELETE /containers/:containerId`

The request layer uses bearer authentication via Clerk tokens, which are attached by the interceptor in `src/lib/useApiAuth.ts`.
